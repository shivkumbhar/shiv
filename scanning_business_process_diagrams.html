Process 02

Vulnerability Detection to Resolution Process

Detailed process flow for a single vulnerability from agent detection through triage, remediation, validation, and closure — with stakeholder handoffs at each stage.

⬤Detect

Agent Detects New CVE

Insight Agent RPM collection cycle completes. Cloud-side assessment identifies new CVE affecting package on Vault node. Finding generated with CVSS score, exploit availability, and affected package details. InsightVM Console syncs findings within 2 hours.

Actor: Rapid7 Platform (automated) → InsightVM Console
◆Classify

Classify by Essential Eight Category

Automated InsightVM rule classifies vulnerability into E8 category based on affected package and asset tag: online service (Vault binary, Go, OpenSSL → ISM-1698), security product (SELinux, auditd → ISM-1699), OS package (kernel, glibc → ISM-1701/1702), or other app (Python, curl → ISM-1700). Correct SLA is automatically assigned.

Actor: InsightVM (automated classification) → Security Operations (manual override if needed)
⚡Ticket

Jira Ticket Auto-Created

InsightVM bi-directional Jira integration creates ticket in Vault Infrastructure project. Ticket includes: CVE ID, affected package, installed vs fixed version, CVSS score, Active Risk score, Essential Eight SLA deadline, ISM control reference, direct link to InsightVM finding, and affected Vault node hostnames.

Actor: InsightVM → Jira (automated) · Assigned to: Platform Engineering
⚙Assess

Platform Engineering Assesses Patch Availability

Platform Eng checks RHEL 9 advisory: dnf updateinfo list --cve CVE-XXXX-XXXXX. If patch available: schedule application. If no patch: escalate to Security Architecture for compensating controls and risk acceptance workflow.

Actor: Platform Engineering · Consult: Vault Administration (for Vault-specific patches)
🧪Stage

Test Patch in Staging Environment

Apply patch on staging Vault cluster. Verify: Vault starts, API responds, cluster forms, seals/unseals correctly, application workload functions. For critical (48h SLA): fast-track staging test (2-hour validation window). For non-critical: standard staging window (24-hour validation).

Actor: Platform Engineering · Approve: Vault Administration
🔧Patch

Apply Patch to Production

Ansible rolling deployment (serial=1). For each node: drain connections (if active), apply patch, verify vault status, verify cluster health, move to next node. For 3-node cluster: total downtime per node ~5 minutes, zero cluster downtime. DR nodes patched within same SLA window.

Actor: Platform Engineering · Notify: SRE (monitoring) + Vault Administration
✓Validate

Agent Auto-Validates Remediation

Insight Agent re-collects RPM inventory within 6 hours. Cloud re-assesses against vuln DB. If CVE no longer present: finding marked as remediated in InsightVM, Jira ticket auto-resolved, SLA compliance timestamp recorded. If CVE persists: Jira ticket auto-reopened, Platform Eng notified.

Actor: Insight Agent + Rapid7 Platform (fully automated)
📋Evidence

Compliance Evidence Captured

InsightVM records: CVE discovery timestamp, SLA deadline, patch application timestamp, validation timestamp, total time-to-remediate. This evidence feeds into monthly E8 compliance reports and quarterly maturity assessments. GRC archives for audit trail.

Actor: InsightVM (automated) → GRC (review and archive)

Process 06

Governance & Review Cadence

Recurring governance activities that ensure the scanning process remains effective and compliant over time.

Daily

Agent Health Check

Automated verification that all Vault nodes have active Insight Agent. Grafana dashboard reviewed by SRE. Any offline agents trigger P1 PagerDuty alert.

Owner: SRE · Automated: Prometheus + Grafana
Weekly

Vulnerability Triage

Security Operations reviews all new findings from past week. Classifies by E8 category, assigns SLA, ensures Jira tickets exist for all Critical/High. Reviews false-positive rate.

Owner: Security Operations · Attendees: Platform Eng, Vault Admin
Weekly

CIS Benchmark Review

Platform Engineering reviews agent-based CIS RHEL 9 and CIS Vault Benchmark results. Investigates new failures. Creates remediation tickets for High/Critical deviations.

Owner: Platform Engineering · Consult: Vault Administration
Monthly

Compliance Report Generation

GRC generates E8 compliance evidence reports from InsightVM: scan frequency logs, patch SLA compliance rates, CIS scores, unsupported software inventory. Distributed to CISO.

Owner: GRC · Approve: CISO · Distribute: All stakeholders
Quarterly

Maturity Assessment

Security Architecture leads formal E8 maturity self-assessment. Gap analysis against target maturity level (ML1 or ML2). Remediation roadmap updated. Results presented to CISO.

Owner: Security Architecture · Approve: CISO
Quarterly

SOAR Playbook Drill

Incident Response executes PB-VAULT-SEAL and PB-VAULT-REVOKE in DR environment. Validates: Vault API call succeeds, PagerDuty fires, Jira ticket created, timing within SLA.

Owner: Incident Response · Observe: SecOps, Vault Admin, SRE
Per Agent Update

Agent Version Validation

Platform Engineering validates new agent version in staging (48h soak). Checks: CPU/memory, Vault latency, vuln data continuity, CIS policy collection. Approves or blocks production rollout.

Owner: Platform Engineering · Consult: SRE
Annual

Professional E8 Audit

External assessor conducts full Essential Eight maturity audit. InsightVM evidence artifacts provided. Findings feed into next year's scanning architecture improvements.

Owner: GRC · Support: Security Architecture, all teams
Process 07

SLA Exception & Risk Acceptance Process

When a vulnerability cannot be patched within the E8 SLA timeframe, the following formal process applies.

Patch not available within SLA?
Vendor dependency, application compatibility issue, or testing failure prevents timely patch.
1. Security Operations Initiates Exception
SecOps creates Risk Acceptance Request in ServiceNow. Includes: CVE details, reason patch cannot be applied, proposed compensating controls, revised remediation date (max 2× original SLA), business impact assessment.
2. Security Architecture Reviews Compensating Controls
Sec Arch evaluates proposed compensating controls: network segmentation, WAF rules, additional monitoring, access restrictions. Must demonstrate the risk is reduced to an acceptable level during the exception period.
3. CISO Approval Required
CISO reviews and formally approves the risk acceptance. Signs the exception with: accepted risk level, compensating controls, hard deadline for remediation, re-review trigger conditions. Exception logged in InsightVM.
CISO signature required
4. GRC Logs Exception for Audit Trail
GRC records the exception in the risk register. Exception appears in monthly E8 compliance report as a documented deviation. Auditors can review the exception chain: request → review → approval → resolution.
5. InsightVM Tracks Revised Deadline
InsightVM exception is configured with revised remediation date. Agent continues monitoring. If exception deadline is breached, escalation re-triggers to CISO. Exception cannot exceed 2× original SLA.
Automated tracking
Process 08

New Vault Node Onboarding Process

Process for bringing a new Vault RHEL 9 node under Insight Agent scanning coverage.

Step 1

Node Provisioned

New RHEL 9 Vault node is provisioned by Platform Engineering. Added to Ansible inventory under vault_servers group with environment and classification variables.

Owner: Platform Engineering
Step 2

Agent Registration Token Generated

Security Operations generates single-use registration token in Rapid7 console. Stores token in Vault KV v2 at secret/data/infra/rapid7/agent-token. Token expires after 1 hour if unused.

Owner: Security Operations
Step 3

Ansible Deployment

Platform Eng runs Ansible playbook targeting new node: ansible-playbook site.yml --limit new-vault-node. Role installs agent, configures bootstrap, applies systemd limits, deploys SELinux policy, runs validation suite.

Owner: Platform Engineering
Step 4

Agent Registration Verified

Platform Eng verifies agent appears in Rapid7 console within 5 minutes. Node is tagged with environment (prod/dr/staging), role (vault-active/standby/dr), and classification (internet-facing/non-internet-facing).

Owner: Platform Engineering · Verify: Security Operations
Step 5

Initial Assessment Confirmed

Within 6 hours, first vulnerability assessment appears in InsightVM. SecOps reviews initial findings. Any pre-existing Critical/High CVEs are immediately triaged and added to remediation queue.

Owner: Security Operations · Action: Platform Engineering
Step 6

CIS Baseline Established

Within 24 hours, Endpoint Broker completes first CIS RHEL 9 benchmark collection. InsightVM displays initial compliance score. Platform Eng remediates any deviations from hardening standard.

Owner: Platform Engineering · Review: Security Operations
Step 7

Node Added to Monitoring

SRE confirms Prometheus process-exporter is collecting agent metrics. Node appears in Grafana Rapid7 Agent Health dashboard. Alert rules cover the new node automatically via label matching.

Owner: SRE
Step 8

Onboarding Complete

Node is fully under continuous scanning coverage. Agent collects 24/7. Vulnerabilities are triaged, patched, and validated per E8 SLA. Node included in next compliance report cycle.

Sign-off: Security Operations + Platform Engineering
