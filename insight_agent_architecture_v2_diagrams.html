Diagram 03 — Critical Gaps

What Rapid7 CANNOT Detect

Five components that Rapid7 has no native capability to assess. Each requires a mandatory compensating control defined in Section 4.

🚨
Critical Finding: HashiCorp Vault is NOT in Rapid7's recurring third-party vulnerability coverage list. The Insight Agent collects RPM packages but Rapid7's vulnerability database has NO HCSEC advisory mapping. Even if Vault is installed as an RPM, Rapid7 will not generate CVE findings for Vault-specific vulnerabilities.
✗ NOT Covered

Vault Binary CVEs (HCSEC)

Auth bypass, privilege escalation, seal vulnerabilities, storage backend issues — the highest-impact CVEs on a Vault deployment. Rapid7 has no HCSEC advisory content in its vulnerability database.

Gap: ISM-1698 (application layer)
✗ NOT Covered

Vault Version Detection (Standalone)

If deployed as a standalone binary (most common), the agent's rpm -qa does not see it. Version is completely invisible. No package inventory entry exists.

Gap: ISM-1698 (cannot identify what's running)
✗ NOT Covered

Embedded Go Runtime CVEs

Go version compiled into Vault binary (e.g., go1.21.5) is invisible to agent and scan engine. Go CVEs (TLS parsing, HTTP/2 DoS, crypto) frequently Critical severity.

Gap: ISM-1698 (dependency of online service)
✗ NOT Covered

Vault Plugin CVEs

External auth methods, secrets engines, audit devices — standalone binaries not tracked by RPM. Plugin-specific vulnerabilities completely undetectable.

Gap: ISM-1700 (ML2 other applications)
✗ NOT Covered

Consul Binary CVEs (if standalone)

Same issue as Vault: if Consul is deployed as a standalone binary, Rapid7 cannot detect its version or match against HashiCorp advisories.

Gap: ISM-1700 (ML2 other applications)
Root Cause
Rapid7's vulnerability database covers OS vendor advisories (RHSA) and a curated third-party list. HashiCorp is not on that list. The agent collects RPM data perfectly — but the cloud-side assessment has nothing to match Vault packages against.
Impact
Vault-specific CVEs are often the highest-impact vulnerabilities in the environment. An auth bypass in Vault = credential ecosystem compromise. These are precisely the CVEs that matter most and they are the ones Rapid7 cannot detect.
Diagram 04 — Compensating Control

HCSEC Advisory Monitoring Pipeline

The mandatory compensating control that closes the Vault CVE detection gap. Runs independently of Rapid7, feeds the same Jira remediation workflow and E8 SLA tracking.

01

Collect Vault Version

Ansible/cron SSHs to every Vault node, runs vault version. Captures both Vault version (e.g., 1.15.6) and Go runtime version (e.g., go1.21.5).

Daily · All nodes · SSH vault-admin
02

Fetch HCSEC Advisories

Python script queries HashiCorp HCSEC advisory feed and Go vulnerability database (vuln.go.dev). Parses CVE IDs, affected version ranges, severity, fixed versions.

Daily · Automated · Python
03

Version → CVE Match

Compares installed Vault version and Go version against affected ranges in advisories. If installed version falls within affected range, generates a vulnerability finding.

Semantic version comparison
04

Create Jira Ticket

Finding submitted to Jira in identical format to Rapid7 tickets: CVE ID, package (vault/go), installed version, fixed version, CVSS, E8 SLA deadline, ISM-1698 reference.

Same workflow as Rapid7
05

SLA Tracking

Same E8 SLAs apply: 48h critical on internet-facing, 2 weeks non-critical. GRC includes HCSEC findings in monthly compliance report alongside Rapid7 findings.

48h / 2wk / 1mo SLA
06

Validate Remediation

After Vault upgrade, next daily collection confirms new version. If CVE no longer affects installed version, Jira ticket is auto-resolved. If persists, ticket reopened.

Next-day validation
Additional Control: RPM Packaging
Package the Vault binary as an internal RPM (vault-1.15.6-1.internal.x86_64). Agent's rpm -qa will then capture the version, providing data foundation for future Rapid7 HCSEC coverage if added.
Quarterly Review
Security Architecture checks quarterly if Rapid7 has added HashiCorp Vault to recurring coverage. If yes, the HCSEC pipeline can be retired and Rapid7 becomes the single source.

What this means
Rapid7 covers the RHEL 9 OS layer comprehensively — kernel, libraries, system services, security products, and all RPM-managed packages. The gap is specifically at the Vault application binary layer: the Vault binary itself, the Go runtime compiled into it, and any external plugins.
